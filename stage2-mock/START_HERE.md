# 2차 예선 모의 체험 키트

앞선 대화에서 정리한 2차 예선 흐름(README에서 R·C 추출 → 기능 묶음 표 → AGENTS.md·PLAN.md → v0·v1·v2 → check.py와 화면으로 확인 → 서술형)을 실제로 한 번 돌려 보는 키트입니다.

> **이 키트의 가정.** 공식 응시 가이드 원문 없이, 대화에서 나온 내용(코딩 에이전트, 최상위 폴더의 README.md와 data/, R·C 조건, 버전별 진행, 서술형)으로 재구성했습니다. 시험 시간과 제출 방식은 실제 안내가 우선입니다.

## 키트 구성

```
stage2-mock/
├── START_HERE.md        ← 지금 이 문서 (진행 방법)
├── exam/                ← 시험 시작 때 열린 최상위 폴더 역할. 이것만 연습 폴더로 복사
│   ├── README.md        ← 과제 (R1~R10, C1~C8, 제출물)
│   └── data/            ← 제공 데이터 8개
├── inbox/
│   └── 01_담당자_추가요청.md   ← 70% 시점에 여는 요구 변경
├── essay.md             ← 서술형 문항 (마지막 20분)
├── grader/
│   ├── grade.py         ← 채점기: 묶음별 점수와 위반 내역
│   └── _reference/      ← 모범 답안·서술형 기준 (끝난 뒤에 보기)
└── tools/make_data.py   ← 다른 시드로 새 데이터 만들기 (두 번째 연습용)
```

## 1. 준비 (5분)

```bash
# 키트 위치가 ~/Flash-game/stage2-mock 라고 할 때
mkdir ~/stage2-practice
cp -r ~/Flash-game/stage2-mock/exam/* ~/stage2-practice/
cd ~/stage2-practice
git init && git add -A && git commit -m "start: 제공 파일"
pwd && ls        # README.md와 data/가 보이면 여기가 최상위
```

그다음 이 폴더에서 코딩 에이전트를 실행합니다.
- Codex를 쓸 수 있으면 `codex` (시험과 같은 환경. `AGENTS.md`를 읽음)
- Claude Code를 쓴다면 `claude`. Claude Code는 `CLAUDE.md`를 읽으므로, AGENTS.md를 만든 뒤 `CLAUDE.md`에 `@AGENTS.md` 한 줄을 넣어 두세요.

`stage2-mock/grader/`, `inbox/`, `essay.md`는 연습 폴더에 복사하지 마세요. 에이전트가 정답 모델을 읽으면 연습이 되지 않습니다.

## 2. 시간표 (기본 150분, 실제 시험 시간에 맞게 비율 유지)

| 시간 | 단계 | 내가 판단할 것 | 끝났다는 기준 |
|---|---|---|---|
| 0–10분 | README 읽기 → R·C를 **기능 묶음 표**로 | 묶음이 사용자 장면 기준인가 | 묶음 3~5개, 묶음마다 "확인 방법" 한 줄 |
| 10–20분 | `AGENTS.md`, `PLAN.md` 작성 | 파일 구조, 수정 금지 규칙이 들어갔나 | 두 파일 커밋 |
| 20–50분 | **v0**: 내 버스 조회 + 기본 배정 | 구현 전 3줄 설명이 내가 원하는 동작인가 | 화면에서 사번 조회됨, 신청자 전원 결과 있음 |
| 50–85분 | **v1**: 정원 지키기 | 우선순위 규칙을 쉬운 말로 설명하게 했나 | 채점기 ③ 만점 |
| 85–105분 | **v2**: 민원 줄이기 + 예외 처리 | 미탑승 수가 v1보다 줄었나 | 채점기 ④⑤ 통과 |
| 105분 | `inbox/01_담당자_추가요청.md` 열기 | 원본을 건드리지 않고 반영했나 | `--stage2` 채점 통과, 보고 3줄 |
| 130–150분 | `essay.md` 서술형 | 규칙 + 수치 + 확인 방법이 다 있나 | `answers.md` 작성 |

매 버전 끝에 할 일: 채점기 실행 → `PROGRESS.md`에 한 줄 기록 → 커밋 → 에이전트에게 "바뀐 동작 3줄, 조건별 처리 규칙을 쉬운 말로" 요청해 `PROGRESS.md`에 붙여 두기 (서술형 재료).

## 4. 채점기 쓰는 법

연습 폴더에서 실행합니다. 맥에서는 `python` 대신 `python3`을 쓰세요. 에이전트에게 시키지 말고 **직접** 돌리세요 (시험에서는 채점기가 없고, 이건 연습용 확인 도구입니다).

```bash
python ~/Flash-game/stage2-mock/grader/grade.py                            # 결과 파일만
python app/main.py &                                                       # 서버 켜고
python ~/Flash-game/stage2-mock/grader/grade.py --url http://localhost:8000   # 화면·API까지
python ~/Flash-game/stage2-mock/grader/grade.py --stage2                   # 담당자 요청 반영 후
```

출력은 대화에서 만든 묶음 ①~⑤ 그대로 나옵니다. ❌ 아래 `└` 줄에 위반한 사번과 이유가 나오니, 그 줄을 그대로 에이전트에게 붙여 주면 됩니다.

| 묶음 | 배점 | 무엇을 보나 |
|---|---|---|
| ① 내 버스 조회 (R1·R2·R5) | 20 | 탑승 시각 계산, 좌석 번호, 화면·API |
| ② 기본 배정 (R3·C1) | 15 | 신청자 전원 한 줄씩, 근무조 일치 |
| ③ 정원 지키기 (R4·C3·C4) | 25 | 정원 초과 0, 우선순위 위반 0, 우선석 |
| ④ 민원 줄이기 (R7·C2·C5) | 20 | 경유 정류장, 2km, 미탑승 수 |
| ⑤ 예외 처리 (R9·C6·C7) | 15 | 사유 코드·대안, 오류 신청, 폐지 노선, 중복 신청 |
| ⑥ 기타 (R6·R8·R10·C8) | 5 | 관리자 현황, 개편 반영, 원본 수정 금지 |

## 5. 이 과제에 숨어 있는 함정 (막혔을 때만 펼쳐 보기)

- `routes.csv`, `buses.csv`는 개편 **전** 데이터입니다. `route_update.md`의 연장 구간 소요 시간과 B-R3-A 정원 변경까지 반영해야 합니다.
